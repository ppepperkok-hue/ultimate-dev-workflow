# API 与通信契约（API Contract）

## 本步定位

选型第 6 层：决定前后端/服务之间怎么说话。

## 决策内容

- API 风格：REST / GraphQL / gRPC / WebSocket / 消息队列
- 契约文档：OpenAPI / gRPC proto / 类型共享包
- 序列化与校验
- 客户端生成与类型生成
- 版本化策略

## 评估维度

- 项目规模与查询复杂度
- 服务间通信量与时延要求
- 前后端并行开发需求
- 契约维护成本

## 原则

- 默认 REST + OpenAPI；复杂聚合再考虑 GraphQL；服务间高性能再考虑 gRPC。
- 契约先于实现：前后端按同一契约并行开发。
- 类型安全：从契约生成类型，不手写两遍。

## AI 适配检查

- 契约先行（OpenAPI/类型生成）让 AI 前后端保持一致
- 契约文件是唯一事实，AI 从契约生成代码
- 版本化策略显式，避免破坏性变更猜错

## 验收门

- API 风格与规模匹配
- 契约工具确定、版本化策略明确
- 用户确认

通过后进入「测试与质量工具链」。
