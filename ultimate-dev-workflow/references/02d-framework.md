# 开发框架（Framework）

## 本步定位

选型第 4 层：决定后端/全栈的应用骨架与约定。

## 决策内容

- Web 框架：FastAPI / Django / Express / NestJS / Go 生态 / Spring 等
- 全栈框架（前后端同仓时）：Next.js / Nuxt / SvelteKit
- 脚手架与项目模板
- 运行时管理：进程管理、环境变量

## 评估维度

- 官方维护与长期版本支持（LTS）
- 生态活跃度与社区规模
- 默认能力：路由、中间件、校验、序列化
- 对后续层的影响：框架绑定的 ORM、客户端、部署约定

## 原则

- 框架默认能力优先，不重复造轮子。
- 与后端语言绑定；不得推翻语言选型，除非有明确 ADR。
- 框架绑定组件时，记录对后续层的约束。

## 验收门

- 框架官方维护、生态活跃、与语言兼容
- 对数据/API/部署层的约束已记录
- 用户确认
