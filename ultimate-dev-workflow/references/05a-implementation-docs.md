# 实施文档拆解（Implementation Docs）

## 本步定位

把 01d 的可执行单元翻译成「施工图」：每个单元一份实施文档，写清做什么、不做什么、怎么验收，再动手写代码。

## 三大核心

1. **明确执行目标**：每个实施文档先定「这个单元要达成什么」——绑定 01d 单元与里程碑，交付结果一句话可讲清，不许模糊。
2. **划定任务边界**：写清做什么、不做什么——只实现本单元，不顺手改别的；接口与数据结构引用既有契约（02f/02e），不新造轮子。
3. **制定验收标准**：验收标准先于实现写定，且全部可执行（测试、lint、类型、真实输入）；说不清怎么验收的不算完成。

## 输入

- 01d 可执行单元（backlog）
- 02 技术栈决策（尤其 02e 数据结构、02f API 契约）
- 03b 通用规则、03d 功能模块模板

## 执行方式

1. 按 03d 模板为每个 backlog 单元生成实施文档。
2. 按三大核心逐块填写：
   - **执行目标**：单元编号、所属里程碑、一句话目标、交付结果。
   - **任务边界**：做什么 / 不做什么；接口与数据结构引用（02f 契约、02e schema）；实现路径（涉及文件、复用模板、新增模块）；依赖与风险。
   - **验收标准**：逐条可执行（测试、lint、类型、真实输入）；验证命令清单。
3. 实施文档评审：对照 03b 规则与 02 选型约束逐份过审；三大核心缺一即退回。
4. 评审不通过退回修改；通过后进入实现。

## 产出

- 实施文档集（`docs/implementation/`），与 backlog 一一对应
- 评审记录

## 验收门

- 每份文档三大核心齐全：目标可讲清、边界无越界、验收可执行
- 每份文档可追溯到 01d 单元与里程碑
- 接口、数据结构引用既有契约，无新造轮子
- 用户确认

通过后进入「分阶段推进验收」。
