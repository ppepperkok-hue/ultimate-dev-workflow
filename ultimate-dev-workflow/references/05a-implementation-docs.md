# 实施文档拆解（Implementation Docs）

## 本步定位

把 01d 的可执行单元翻译成「施工图」：每个单元一份实施文档，写清做什么、怎么做、怎么验收，再动手写代码。

## 输入

- 01d 可执行单元（backlog）
- 02 技术栈决策（尤其 02e 数据结构、02f API 契约）
- 03b 通用规则、03d 功能模块模板

## 执行方式

1. 按 03d 模板为每个 backlog 单元生成实施文档。
2. 每份实施文档包含：
   - **单元编号与所属里程碑**：回溯 01d，可追溯。
   - **目标与范围**：做什么、不做什么。
   - **接口与数据结构**：引用 02f 契约与 02e schema，不另造一套。
   - **实现路径**：涉及文件、复用模板、新增模块。
   - **验收标准**：可执行（测试、lint、类型、真实输入）。
   - **依赖与风险**。
3. 实施文档评审：对照 03b 规则与 02 选型约束逐份过审。
4. 评审不通过退回修改；通过后进入实现。

## 产出

- 实施文档集（`docs/implementation/`），与 backlog 一一对应
- 评审记录

## 验收门

- 每份文档可追溯到 01d 单元与里程碑
- 接口、数据结构引用既有契约，无新造轮子
- 验收标准全部可执行
- 用户确认

通过后进入「分阶段推进验收」。
