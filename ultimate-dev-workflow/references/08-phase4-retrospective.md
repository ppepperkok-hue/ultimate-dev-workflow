# Phase 4 复盘（Retrospective）

## 本步定位

交付后回头收账：做成了什么、哪里偏了、下次怎么改。复盘的产出要能回写，不让经验烂在聊天记录里。

## 复盘内容

1. **成果核对**：对照 01b 目标，哪些达成、哪些没达成、为什么。
2. **偏差记录**：翻阶段小结（05b）与验证记录，找出漂移、返工、踩坑。
3. **方法论改进**：哪些流程环节卡了、哪些规矩有用，形成可执行改进。
4. **经验回写**：改进回写本 skill（终极全流程开发 skill 自身迭代）；项目经验写入记忆/知识库。
5. **归档**：项目归档，产物与文档清单收尾。

## 原则

- 复盘要产出行动项，不许只写感想。
- 改进项要落到文档、模板或规则，否则不算完成。

## 经验回写机制

1. 把改进整理成具体条目：现象 → 原因 → 规则修改建议。
2. 修改本 skill 对应文件：规则类改 `references/`，模板类改 `templates/`，资产类改 `assets/`。
3. 跑 `quick_validate.py` 校验 skill 结构，改动随项目一起提交。
4. 可复用经验写入长期记忆（angel-memory），标注项目与适用场景。

## 验收门

- 复盘记录完成（成果/偏差/改进三部分）
- 可复用经验已回写（skill 或记忆库）
- 行动项有主有期
- 用户确认

通过后整个流程闭环，回到 Phase 0 开启下一轮（新项目或下一大阶段）。
