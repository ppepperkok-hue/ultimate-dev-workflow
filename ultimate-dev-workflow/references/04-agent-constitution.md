# Agent 宪法（Agent Constitution）

## 本步定位

为参与项目的所有 agent（和人类协作者）立共同行为规则。宪法的前提是「被读到」：读不到的规则等于不存在。

## 核心：规则必须被读取到

1. **指定位置配置规则**：规则只放约定位置（项目根 `AGENTS.md`、全局 `AGENTS.md`、`rules.md`），不散落。
2. **自动续入上下文**：利用 Codex/agent 的 `AGENTS.md` 自动加载机制，规则随会话自动进入上下文，不靠手动提醒。
3. **任务前全量加载**：任务开始前全量读取指定位置，只读片段等于没读。
4. **指定位置必须要被读取到**：有验证手段确保读取真实发生；未读到不许开工。

## 规则条款（内容骨架；位置与加载机制由四步确定）

1. **验证纪律**：任务完成 = 可用测试通过 + 类型检查通过 + lint 无阻塞 + 真实/代表性输入跑通。修 bug 先复现或写失败测试。
2. **失败显式化**：不静默吞错、不假装绿灯；验证失败必须修复后重跑。
3. **配置驱动**：环境差异进配置；不硬编码密钥、路径、端口。
4. **幂等**：脚本和操作可重复执行，结果一致。
5. **最小改动**：只改任务相关文件，不重写、不格式化无关代码；不覆盖用户改动。
6. **文档如实**：代码、文档、交付说明一致，不夸大结果。
7. **审查义务**：交付前自审；重要改动提交审查，收到审查意见先验证再回应。
8. **权限边界**：破坏性操作需用户明确批准；不记录敏感信息。
9. **沟通纪律**：进度、卡点、风险如实报告；缺凭据/权限、外部环境不可得时才停下询问。
10. **冲突规则**：`AGENTS.md` 优先于通用习惯；与用户最新指令冲突时，以用户最新指令为准并说明差异。

## 执行方式

1. 按 04a 确定位置，把条款写入指定位置。
2. 按 04b 验证自动加载路径。
3. 按 04c 定任务前加载流程。
4. 按 04d 加强制验证手段。
5. 用户确认后生效；修改宪法走变更记录。

## 验收门

- 规则只存在于指定位置，无散落副本
- 自动加载路径实测有效
- 任务前全量加载流程可执行
- 强制读取验证可检查
- 用户确认

宪法确认后，进入 Phase 1 开发（[05-phase1-development.md](05-phase1-development.md)）。
