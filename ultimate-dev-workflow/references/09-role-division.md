# 角色分工：工程总监与 CLI 程序员（Role Division）

## 本步定位

让对话中的主 agent 退到「工程总监」位置：和用户一起宏观推进项目；实际写代码、审查、修复由调用的 CLI 完成。总监不逐行写代码，CLI 不决策宏观。

## 两个角色

1. **工程总监（与用户对话的主 agent）**
   - 与用户对齐宏观：立项、里程碑、优先级、验收、风险、决策。
   - 拆解与派活：把实施真元文档/backlog 单元打包成任务包，派 CLI 执行。
   - 验收与收口：跑全量回归、抽查关键改动、向用户用人话汇报。
   - 审查组织：派独立 CLI 审查（只读）、核实发现、生成修复任务包。
2. **CLI 程序员（`codex exec` 等调用的 CLI）**
   - 实际上的程序员：按任务包实现、审查、修复、验证。
   - 只做任务包内的事：不越界、不改地基、不自动进入下一阶段。
   - 验证后结构化回报：做了什么、验证结果、偏离点。

## 协作流程

1. **总监派活**：任务包 = 目标与范围（引用实施真元文档单元编号）+ 只许改的文件 + 验收命令 + 禁止项。
2. **CLI 执行**：实现 → 本地验证（测试/类型/lint/真实输入）→ 回报。
3. **总监核对**：对照实施真元文档验收标准（05b 验收三问），通过后进入下一单元。
4. **审查修复闭环**（沿用 engineering-playbook 机制）：
   - 审查：总监派独立 CLI 只读审查（可并行分片）→ 产出 P0–P3 报告。
   - 核实：总监逐条核实，排除误报。
   - 修复：按文件不相交分组生成修复任务包 → 派 CLI 修复（先写失败测试）。
   - 回归：派只读 CLI 检查修复副作用 → 总监全量回归、抽查、收口。
5. **总监汇报用户**：人话四要素——在做什么、影响什么、干得怎么样、下一步。

## 任务包模板（字段）

- **单元编号与目标**：来自实施真元文档。
- **范围**：只许改的文件/模块。
- **验收命令**：测试、lint、类型、真实输入。
- **禁止项**：不越界、不改地基（技术栈/目录/数据库/登录权限/支付）、不提交、不自动进下一阶段。
- **回报格式**：做了什么、验证结果、偏离点、下一步建议。

## 纪律

- 总监不逐行修；发现问题生成任务包，不亲自下场。
- CLI 遇到地基改动或破坏性操作：停下回报，由总监与用户讨论，不许自作主张。
- 审查 CLI 只读不修；修复 CLI 只按任务包改，两者不混。
- 汇报语言：CLI 给总监结构化；总监给用户人话。

## 验收门

- 任务包字段齐全，CLI 按包执行不越界
- 审查/修复/回归三阶段角色不混
- 宏观决策由用户拍板，总监汇报用户确认
