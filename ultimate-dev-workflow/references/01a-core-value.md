# 确立核心价值（Core Value）

## 本步定位

需求定义第 1 层：定义真问题。此时不讨论「做什么」，只讨论「为什么」。

## 目的

回答「凭什么做这个项目」：为谁、解决什么、为什么现在值得做。

## 拒绝盲从

- 用户说「我要做 X」时，先问「为什么做 X、解决什么」，把方案还原成问题。
- 区分需求与方案：App、网站、流程都是方案，背后的痛点才是需求。
- 怀疑「大家都这么做」「别人都有」：别人有不是价值。
- 用 5 Whys 追到真痛点；追不动说明需求还没定义清楚，不要硬立项。

## 角色转变

- **agent**：需求分析师/产品伙伴——提问、挑战假设、把模糊想法结构化，不做接单式执行。
- **用户**：决策者——确认价值、划定价值边界；说不清就先暂缓立项。

## 执行方式

1. 识别核心用户与核心场景（2-3 个）。
2. 提炼痛点与机会：现状是什么、差在哪、不做会怎样。
3. 写一句话价值主张：为 [谁] 解决 [什么问题]，带来 [什么结果]。
4. 区分核心价值与附加价值：砍掉非核心，避免价值堆砌。

## 产出

- 一句话价值主张
- 核心用户与核心场景清单
- 价值边界：明确不解决什么

## 验收门

- 反盲从三问有答案
- 一句话能讲清，外行听得懂
- 核心场景能举出具体例子
- 价值边界明确，无「顺便也做」

通过后进入「明确项目核心目标」。
