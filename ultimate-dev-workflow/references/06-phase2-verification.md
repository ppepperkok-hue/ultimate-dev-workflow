# Phase 2 验证（Verification）

## 本步定位

开发阶段每个子阶段已做过验收（05b），本步是收口前的全量验证：把整个项目当作整体过一遍，确认没有「单点绿、整体挂」。

## 核心：验证纪律全面执行

- 把 04 宪法的验证纪律（第 1 条）放大到全项目：测试、类型、lint、真实/代表性输入。
- 不能只信开发阶段的局部验证，整体链路必须重新跑。

## 验证内容

1. **全量自动化**：全部测试套件、类型检查、lint、构建，一次跑通。
2. **真实场景验证**：按 01b 成功标准，用代表性输入跑核心链路（入口到业务到存储到响应）。
3. **边界与失败**：模拟边界情况和代表性失败，确认错误路径不静默吞错（04 宪法第 2 条）。
4. **回归**：修过 bug 的地方重跑相关测试；改动引入的新行为都有覆盖。
5. **对照立项**：把成果对照 01b 目标与成功标准逐条核验，留下证据。

## 审查

- 交付前自审（04 宪法第 7 条）。
- 重要项目做代码审查/安全审查：按需使用 review-agent、工程审查清单、安全扫描。
- 审查发现的问题修复后重跑全量验证。

## 验收门

- 全量验证命令全绿，无已知未修复缺陷
- 01b 成功标准逐条达成并有证据
- 边界与失败路径有验证记录
- 审查意见已处理
- 用户确认

通过后进入 Phase 3 交付。
