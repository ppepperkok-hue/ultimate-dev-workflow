# 功能细化拆解（Feature Breakdown）

## 本步定位

需求定义第 3 层：定义范围——做什么、不做什么。

## 目的

把目标拆成功能粒度：用户能用它做什么、边界在哪。

## 拒绝盲从

- 每个功能必须回溯到目标；回溯不上的孤儿功能一律砍。
- 不盲从竞品功能表：竞品有不等于你需要。
- 用户说「顺便加个功能」时，验证它服务哪个目标，答不上就不做。
- 范围蔓延是常态：不做清单与做清单同等重要，必须写进文档。

## 角色转变

- **agent**：范围管理者——做取舍、排依赖、对用户说「不」并给出理由。
- **用户**：取舍者——在价值与成本之间拍板，而不是照单全收。

## 执行方式

1. 按核心场景导出功能清单，用用户故事格式：作为 [角色]，我想要 [功能]，以便 [收益]。
2. 每个功能标注优先级，并关联所属目标。
3. 明确范围边界：做 / 不做（非目标）清单。
4. 检查功能依赖与实施顺序，标记前置功能。

## 产出

- 功能清单（编号、优先级、所属目标）
- 做 / 不做清单
- 功能依赖关系

## 验收门

- 反盲从三问有答案
- 功能与目标一一对应，无「孤儿功能」
- 不做清单明确，无「再说」「看情况」
- 依赖顺序可排，无循环依赖

通过后进入「拆解为可执行单元」。
