# 确定最小架构范围（Minimum Scope）

## 本步定位

把「全量功能」压成「最小可验证架构」：只搭支撑首个里程碑的架构，其余留到以后按规则增量加入。

## 拒绝全量

- 立项清单里的功能 ≠ 本期架构范围。
- 只从 01d 的可执行单元中取首个里程碑（最小可验证版本）所需的功能。
- 「以后可能用到」是架构毒药：可以留扩展点，不做实现。

## 执行方式

1. 从 backlog 取出首个里程碑的功能单元。
2. 识别支撑这些单元的最小横切能力：配置、日志、错误处理、路由、数据库连接、测试框架。
3. 列出「本期不做」清单：延迟功能、未来扩展点、可后补的机制。
4. 每条范围决策记录理由，与里程碑一一对应。

## 产出

- 本期架构范围（做 / 不做）
- 最小横切能力清单
- 范围决策记录

## 验收门

- 范围能支撑首个里程碑端到端跑通
- 无全量功能，无「顺便搭上」的机制
- 「本期不做」清单明确
- 用户确认

通过后进入「定义通用规则」。
