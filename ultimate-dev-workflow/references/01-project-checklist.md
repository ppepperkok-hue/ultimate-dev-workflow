# 立项规划（Project Planning）

## 目的

动工前把「价值、目标、范围、任务」四层钉死，避免带着模糊目标进入技术选型和开发。本步唯一产出是一份经用户确认的立项清单。

## 输入

- 用户的一句话需求、模糊想法、或已有文档
- 现有系统约束（如为存量项目立项时）

## 四步流程（顺序执行，前一步产出是后一步输入）

1. **确立核心价值** — [01a-core-value.md](01a-core-value.md)
2. **明确项目核心目标** — [01b-project-goals.md](01b-project-goals.md)
3. **功能细化拆解** — [01c-feature-breakdown.md](01c-feature-breakdown.md)
4. **拆解为可执行单元** — [01d-executable-units.md](01d-executable-units.md)

每一步先读对应文档，按「输入 → 决策 → 产出 → 验收门」执行，产出写入 `docs/project-plan/` 下对应文件；四步完成后汇总为 `docs/project-checklist.md`，交用户确认。

## 全局约束与风险（贯穿四步，随时更新）

- **约束**：时间、预算、人员、运行环境、合规要求
- **风险与前提**：Top 3-5 风险，每条附应对措施或规避策略
- **决策记录**：为什么做、为什么现在做、否决过什么方案

## 验收门

- 价值一句话可讲清，外行听得懂
- 核心目标全部可测量、可验收
- 功能与目标一一对应，做/不做边界明确
- 每个功能都有可执行单元，单元可估算、可独立验收
- 用户逐项确认，无未决的 P0 问题

未通过验收门不得进入选技术栈。用户中途改需求时，先回退到对应子步骤更新，再继续。
