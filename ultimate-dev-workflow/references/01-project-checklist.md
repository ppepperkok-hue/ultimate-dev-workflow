# 立项清单（Project Checklist）

## 目的

动工前把「做什么、为什么做、做成什么样、边界在哪」钉死，避免带着模糊目标进入技术选型和开发。本步唯一产出是一份经用户确认的立项清单。

## 输入

- 用户的一句话需求、模糊想法、或已有文档
- 现有系统约束（如为存量项目立项时）

## 执行方式

1. 按下方清单逐项提问并填写，不替用户拍板成功标准。
2. 用户明确说「不知道/你来定」的项，给出建议并标注「待确认」。
3. 完整填写后向用户复述，确认后归档为 `docs/project-checklist.md`。

## 清单字段（骨架）

1. **项目名称与一句话定位**：用什么、解决谁的什么问题。
2. **目标与成功标准**：可测量、可验收；每条成功标准对应一个验收方式。
3. **用户与核心场景**：主要使用者、2-3 个核心使用路径。
4. **范围边界**：明确「做」与「不做」；不做清单（非目标）与做清单同等重要。
5. **约束**：时间、预算、人员、运行环境、合规要求。
6. **风险与前提**：Top 3-5 风险，每条附应对措施或规避策略。
7. **交付物与验收方式**：代码、文档、部署产物各自怎么算完成。
8. **决策记录**：为什么做、为什么现在做、否决过什么方案。

## 验收门

- 成功标准全部可测量、可验收
- 「不做」清单明确，无「再说」「看情况」
- 风险有应对，前提条件有主
- 用户逐项确认，无未决的 P0 问题

未通过验收门不得进入选技术栈。用户中途改需求时，先更新本清单再继续。
