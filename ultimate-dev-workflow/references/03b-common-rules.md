# 定义通用规则（Common Rules）

## 本步定位

一次性定下全项目统一规则，让以后每个功能都按同一套规则开发，不靠临场发挥。

## 规则域（骨架）

1. **目录与命名**：文件、组件、接口、模块的命名与位置约定。
2. **依赖方向**：模块边界与依赖规则，禁止循环依赖。
3. **错误处理与日志**：错误类型、日志级别、禁止静默吞错。
4. **配置与密钥**：环境变量、默认值、敏感信息注入方式。
5. **接口契约**：入参出参、校验、错误码、版本化。
6. **测试规则**：测试布局、命名、最低覆盖、验证命令。
7. **代码风格与提交**：lint、格式化、commit 规范。

## 执行方式

1. 逐域定规则，先定可执行的（命令、模板），再定行为约定。
2. 每条规则绑定检查手段：lint 规则、测试、模板、CI 检查。
3. 写入 `docs/architecture/rules.md`（或由项目 AGENTS.md 引用）。
4. 规则变更走记录流程，不许悄悄改。

## 验收门

- 每条规则有检查手段，无「凭感觉遵守」
- 规则文档与项目实际一致
- 用户确认

通过后进入「搭建最小骨架」。
