# 选技术栈（Tech Stack）

## 本步定位

在立项清单（已定义需求）之后，把需求翻译成技术选型。技术栈按八层逐步决策，前一层约束后一层。

## 八层流程（顺序执行）

1. **前端技术栈** — [02a-frontend.md](02a-frontend.md)：框架、语言、状态管理、样式、构建
2. **UI 组件库** — [02b-ui-library.md](02b-ui-library.md)：组件库、设计系统、主题、图标
3. **后端语言** — [02c-backend-language.md](02c-backend-language.md)：语言与运行时
4. **开发框架** — [02d-framework.md](02d-framework.md)：后端/全栈框架、脚手架
5. **数据与存储** — [02e-data-storage.md](02e-data-storage.md)：主库、缓存、对象存储、ORM
6. **API 与通信契约** — [02f-api-contract.md](02f-api-contract.md)：API 风格、契约、客户端生成
7. **测试与质量工具链** — [02g-tooling.md](02g-tooling.md)：测试、lint、类型检查、CI/CD
8. **部署、可观测性与安全** — [02h-deploy-observability.md](02h-deploy-observability.md)：托管、监控、密钥、回滚

纯前端/纯后端/单脚本项目跳过不适用的层，但必须记录「本层不适用」及原因。

## 执行方式

1. 逐层执行：候选 → 对比表 → 推荐 ADR（背景、选项、决定、后果）→ 否决项记录。
2. 每层决策写入 `docs/tech-stack.md` 对应章节。
3. 层间冲突（如框架绑定语言）先决高层，再回退修正，留决策记录。
4. 全部完成后锁定版本：写 lock file，固定运行时与关键依赖版本。
5. 用户逐层确认，最后整体确认。

## 通用评估维度

- 生态成熟度与官方支持
- 团队/用户熟悉度与学习成本
- 长期维护成本（社区活跃度、发布节奏）
- 部署与运行环境适配
- 许可证与供应商风险
- 性能与规模预期
- 与既有系统的集成面
- 验证成本（测试、构建、部署链路是否顺手）

## 原则

- 不追新：默认成熟稳定，除非立项清单明确需要新特性。
- 最少依赖：每个依赖都要有理由，能少装就少装。
- 官方文档优先：第三方库行为以官方文档和锁定版本为准。
- 可复现：同一份 lock file 在任意环境产生相同构建。
- 需求优先：立项清单是选型的唯一裁判，技术喜好不许压过需求。

## 验收门

- 八层逐层有决定，跳过层有理由
- 每个选型有 ADR，否决项有记录
- 版本锁定、许可无风险、构建可复现
- 用户确认无异议

通过后进入项目架构。换栈必须走同一流程并更新 `docs/tech-stack.md`。
