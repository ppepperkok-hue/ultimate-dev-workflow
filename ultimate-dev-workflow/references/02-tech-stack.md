# 选技术栈（Tech Stack）

## 目的

基于立项清单选择技术栈，每个选择有理由、版本可复现、不追新不拍脑袋。

## 输入

- 已确认的立项清单（尤其：项目类型、约束、团队熟悉度、交付物）

## 执行方式

1. 由项目类型导出候选栈：Web 前端/后端、桌面、CLI、移动、游戏、数据管道、多 Agent 系统等。
2. 按评估维度对比候选，产出对比表。
3. 给出推荐与理由（短 ADR 格式：背景、选项、决定、后果），记录否决项。
4. 锁定版本：写 lock file，固定运行时与关键依赖版本。
5. 产出 `docs/tech-stack.md`，经用户确认后进入架构设计。

## 评估维度

- 生态成熟度与官方支持
- 团队/用户熟悉度与学习成本
- 长期维护成本（社区活跃度、发布节奏）
- 部署与运行环境适配
- 许可证与供应商风险
- 性能与规模预期
- 与既有系统的集成面
- 验证成本（测试、构建、部署链路是否顺手）

## 原则

- 不追新：默认选成熟稳定方案，除非立项清单明确需要新特性。
- 最少依赖：每个依赖都要有理由，能少装就少装。
- 官方文档优先：第三方库行为以官方文档和锁定版本为准。
- 可复现：同一份 lock file 在任意环境产生相同构建。

## 验收门

- 每个选型有理由，否决项有记录
- 版本锁定、许可无风险、构建可复现
- 用户确认无异议

通过后进入项目架构。后续换栈必须走同一流程并更新 `docs/tech-stack.md`。
