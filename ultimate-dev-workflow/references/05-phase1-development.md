# Phase 1 开发（Development）

## 本步定位

承接 Phase 0：把立项、选型、架构、宪法落成真实代码。开发不是直接开写，而是「先出实施文档，再分阶段推进验收」。

## 与 Phase 0 的衔接

- 输入：01d 可执行单元（backlog）、02 技术栈约束、03a 最小架构范围、03d 功能接入模板、04 宪法的验证纪律。
- 每段代码都要能回答：对应哪个单元、遵循哪条规则、怎么验收。

## 两步流程（顺序执行）

1. **实施文档拆解** — [05a-implementation-docs.md](05a-implementation-docs.md)
2. **分阶段推进验收** — [05b-staged-delivery.md](05b-staged-delivery.md)

## 阶段路线

- 每个阶段 = 一个里程碑或功能批次；阶段内走：实现 → 验证 → 自审 → 阶段验收。
- 验收不过不进入下一阶段，不许带病推进。

## 验收门（阶段级）

- 实施文档与 backlog 一一对应，可追溯
- 验证命令全绿（测试/类型/lint/真实输入）
- 通用规则符合（03b），无绕过
- 阶段小结记录偏差与风险
- 用户确认

通过后进入 Phase 2 验证（待补）。
