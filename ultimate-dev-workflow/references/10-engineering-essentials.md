# 工程红线与反模式（Engineering Essentials）

来源：engineering-playbook（已并入本 skill，完整版归档于 `C:\Users\Administrator\skills-archive\dev\merged-2026-08-12\engineering-playbook`）。

## 工程红线（不可妥协）

1. 先定义「完成」再动手：完成标准可验证（测试/命令/可观察结果），验收不靠感觉。
2. 验证纪律：可用时跑测试、类型检查、lint、真实或代表性输入；修 bug 先复现或写失败测试；视觉工作检查渲染结果。
3. 失败必须显式化：错误码、日志、状态字段、留痕；绝不静默吞错，「看起来成功但什么都没发生」是最高优先级 bug。
4. 配置驱动：路径、密钥、预算、参数全部环境变量化或配置化，禁止硬编码机器路径。
5. 幂等与防抖：写入操作幂等（同一输入重复执行结果一致）；空载荷防抖；并发用原子锁 + 陈旧回收 + 所有退出路径释放。
6. 文档如实：README、状态、能力声明里的每个数字（节点数/测试数/版本/功能）必须与代码一致。
7. 审查证据优先：每条结论带证据（文件:行号/输出/日志/复现），P0–P3 分级，报告可复现。
8. 渐进式交付：先最小可用链路跑通，再接外部；先单路，再并行；每阶段有检查点才前进。
9. 外部系统先抓真实请求：接第三方 API/平台前用真实请求确认接口、鉴权、限额、风控，不猜文档。
10. 测试隔离：测试不写真实数据库、不触发真实外部调用、不碰生产配置。

## 执行质量门（每次改动四道门，任一不过就停）

1. **DECIDE**：一句话需求拆成 ≤ 3 个独立维度逐项给结论；架构判断带证据锚点；推翻旧建议要显式「撤回」；now/later 分清，禁止提前造扩展点。
2. **BUILD**：垂直切片，一片 ≤ 100 行；写一片 → 跑测试 → 提交，不攒堆。
3. **VERIFY**：五轴检查（正确性/边界与错误处理/集成/安全）+ 测试 + 构建；修 bug 先写失败测试。
4. **POLISH**：去 AI 味、状态三态完整、遵循项目风格、文档同步。

## 反模式族（F1–F12，审查与修复时按族治理）

| 族 | 反模式 | 静态扫描示例 |
| --- | --- | --- |
| F1 | 裸 JSON 解析 | `rg -n "json\.loads\(" --glob "*.py"` |
| F2 | 裸类型转换 | `rg -n "(?<!_)\bint\(" --glob "*.py"` |
| F3 | 静默吞错 | `rg -n "except\s*:|except Exception"` |
| F4 | 假绿灯 | `rg -n "ok.?=.?True|exit\(0\)"` |
| F5 | 死代码 | `rg -n "^def "` 后核对引用 |
| F6 | 硬编码路径/密钥 | `rg -n 'C:\\|/home/|YOUR_|your-.*-id'` |
| F7 | 类型守卫缺失 | `rg -n "\.get\(|\.items\(\)"` |
| F8 | 状态语义映射不一致 | 对照状态常量与消费方 |
| F9 | 资源泄漏 | `rg -n "connect\(|open\(|mkstemp"` |
| F10 | 注入类 | 对照 F6 注入面扫描 |
| F11 | 编码/行尾混乱 | ps1 中文带 BOM 或全 ASCII |
| F12 | 测试假断言 | `rg -n "assertTrue\(True\)"` |

治理顺序：先按族全库清理（先治族，再治点），族级任务包派独立 CLI；无法治理的实例必须显式豁免并写理由。

## 老板汇报制（工程总监向用户汇报）

动手前三步：技术评估（目标与验收标准、影响范围、风险与成本、回退方式）→ 工程表（分步实施表，每步可验证可回退）→ 汇报（用用户听得懂的话讲清决策点，确认后再动手）。

汇报四要素（缺一不可）：在做什么（一句话人话）· 影响什么（范围/成本/风险/回退）· 干得怎么样（验证证据，不是「应该没问题」）· 下一步（明确后续动作或需用户拍板的事）。

长项目维护四份活文档：`requirements.md / plan.md / implementation.md / deployment.md`；写新计划前归档旧计划；与 AI 协作用 4S 法则一次给全上下文，对话超 15 轮重新开。
