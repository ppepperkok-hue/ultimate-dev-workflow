# 通用开发流程（详细版）

## Phase 0 · 需求与决策

动作：

- 写下目标与「完成 = 什么」（可观察、可验证）。
- 划定自动化/人工边界：哪些环节必须人确认（高危、不可逆、涉及外部身份），哪些全自动。
- 定预算与规模：影响技术选型与是否要成本台账/熔断。
- 定技术栈：默认选熟悉且验证过的组合；换栈必须有明确理由（性能/生态/结果优先，不为换而换）。
- 调研外部依赖：抓真实请求确认接口路径、鉴权方式（Cookie/Token/签名）、限额、风控、版本兼容。

产出：一页决策记录 `docs/planning/decision.md`。

常见坑：没调研就写外部集成（pitfalls 6）；自动化边界不清导致不可逆操作无人确认。

## Phase 1 · 项目骨架

动作：

- 目录结构按职责分层（如 `pkg/` 库、`tools/` 脚本、`tests/`、`docs/`）。
- 集中配置模块：路径、env 加载、常量，全部从一处读取。
- 数据层：建表 + 迁移 + 连接工具；外键、唯一约束、WAL（如用 SQLite）。
- 测试框架 + 冒烟测试（不依赖外部服务）。
- `.env.example` 覆盖所有运行参数：密钥、Cookie、预算、单价、解释器路径、项目根。

检查点：

- 测试全绿（纯本地）。
- 数据层能建库并列出核心表。
- 配置模板完整。

常见坑：路径硬编码（pitfalls 13）；测试直接连真实库（pitfalls 14）；编码不一致（pitfalls 12）。

## Phase 2 · 最小核心链路（先离线）

动作：

- 做一个最小闭环：入口 → 核心处理 → 输出落库/落盘 → 可验证。
- 统一客户端/适配层（如 LLM 客户端、HTTP 客户端）：重试、空响应报错、成本/用量记账、Mock 模式。
- 业务参数资产化：提示词、配置、模板放独立文件（frontmatter/声明式），由生成器产出最终产物，禁止手改产物。
- 先单路跑通，再拆并行分支。

检查点：

- 最小链路产出真实结果并落库。
- 空输入/空结果显式报错，不静默成功。
- 同输入重复执行结果幂等。

常见坑：空结果当成功（pitfalls 4）；输出被截断（pitfalls 5）；手工拼产物语法错误（pitfalls 2）。

## Phase 3 · 外部集成与健壮性

动作：

- 抓真实请求：方法、URL、请求头、表单字段、签名要求，全部记录后写代码。
- 实现调用 + 错误码映射（平台错误码 → 本地状态/提示）。
- 状态机：成功 / 失败待重试 / 失败留痕，失败保留可补发状态。
- 重试策略：瞬时错误（429/5xx）重试，其余直接失败；幂等键防重复执行。
- 熔断：预算、次数、并发上限触发即停，写告警。

检查点：

- 真实小规模调用成功。
- 构造失败场景（缺参数/超限/格式错）验证错误处理。
- 同一操作重复调用不产生重复副作用。

常见坑：没抓真实请求（pitfalls 6）；失败静默（红线 3）；并发双发（pitfalls 7）。

## Phase 4 · 复杂度扩展

动作：

- 并行分支：各分支独立上下文，一分支失败不拖死其他；失败原因写库可补发。
- 多模块/多 Agent：上下文 ID（业务主键）从入口穿透到每个调用并校验；模块间用事件/活动日志记录「谁干了什么」。
- 知识/数据层（如需要）：版本化、按需调用（不常驻上下文）、增量同步、人工采纳的更新走草案。
- 后台任务：状态机（running/awaiting/parked/cancelled/failed）、心跳自愈、取消在写入前校验、轮次/超时上限。
- 记忆/状态持久化：写入结构化沉淀，供下次消费；保留窗口自动清理。

检查点：

- 扩展后原链路回归全绿。
- 一分支失败不影响健康分支；失败显式留痕。
- 多实例/多业务数据不串扰。
- 后台任务可取消、可自愈、不无限烧资源。

常见坑：上下文 ID 不穿透（pitfalls 9）；僵尸任务（pitfalls 8）；数据串扰。

## Phase 5 · 交付界面

动作：

- CLI / 面板 / 桌面应用 / 文档，按功能优先级组织（核心状态、今日任务、上次执行为主；统计、历史为次）。
- 每个按钮有真实动作链（UI → API → handler → 副作用 → 刷新）；每个显示字段有数据源。
- 状态三态：加载/空/错误都有合理 UI；页面级错误边界。
- 实时通道：推送 + 轮询双通道；快照只补头部不覆盖完整数据。
- 时间统计用本地时区，禁止 UTC 与本地混用。
- 硬编码数字动态化（版本、节点数、上限从后端取）。

检查点：

- 交互走查一遍，无死模块、无假数据。
- 前端测试 + 构建通过。
- 桌面/壳：生命周期正确（进程拉起与回收、托盘、通知、自启）。

常见坑：假数据死模块（pitfalls 11）；实时通道单点；时区错位。

## Phase 6 · 验证与部署

动作：

- 全量测试（单元 + 集成 + 端到端 + 产物校验）。
- 端到端实跑：从入口到落库到通知/发布，逐节点观察。
- 部署：渲染/构建 → 校验 → 推送 → 激活；密钥与配置走环境变量。
- 运维：备份、开机自启/守护进程统一托管、异常恢复工具（释放锁/手动补跑）、手动触发入口、告警。

检查点：

- 一次真实端到端成功，日志/状态/成本全部落账。
- 重启/断电后能恢复且不双发。
- 部署文档与代码一致。

常见坑：只测单元不测端到端；运维缺失（无备份/无恢复工具）；文档失真（红线 6）。
