# 执行质量门（每次改动都过）

流程管「整个项目怎么走完」，本文件管「每次改动怎么过关」。写任何代码前按四门顺序走，任一不过就停下，不进下一门。

## Gate 1 · DECIDE（动手前）

- **需求分解**：把一句话需求拆成 ≥3 个独立维度（如登录 = 认证策略/存储/中间件/UI/安全），逐维度给出结论；需要用户裁决的维度先停下来问，不要一次全写。
- **证据锚点**：任何架构判断给出 1–3 个锚点（`文件:行号`、配置项、当前指标）；没有锚点就是在猜。
- **显式撤回**：新证据推翻旧建议时，明确写「撤回 X：原因。替代方案」，不许无声反转。
- **now / later 边界**：now 只放本次必须落地的能力；later 只留一行占位 + 触发条件，禁止现在造扩展点。
- **公共符号**：对外 API/示例/导出符号在文档注释里声明稳定性：`@stable` / `@experimental` / `@internal`。

## Gate 2 · BUILD（增量交付）

- 垂直切片：一次只做一条完整功能线（UI + 逻辑 + 数据一起通），不做横向大层。
- 单片规模：每片 ≤100 行（或本仓库合理上限），超过就拆。
- 每片三连：写完这一片 → 跑测试 → 提交这一片，不攒一堆再提交。

### 量化硬限制（超过 = 必须重写/拆分）

| 粒度 | 软上限 | 硬上限 | 超过怎么办 |
|---|---|---|---|
| 单文件 | 400 行 | 500 行 | 按职责拆分 |
| 单函数 | 80 行 | 120 行 | 抽 helper |
| 嵌套深度 | 2 | 3 | early return / 守卫子句 |
| 单次提交 | 80 净新增 | 100 净新增 | 拆两个切片 |
| 单 PR | 300 行 | 1000 行 | 拆栈式 PR |

### 命名与错误处理纪律

- 禁用无信息词：`data` / `result` / `tmp` / `info` / `item` / `manager` / `helper` / `util`（项目已有约定除外）；名字要表达「是什么 + 为什么」；谓词函数 `is*/has*/can*/should*` 前缀；副作用函数动词开头。
- 禁止空 catch / 裸 `unwrap()` / `_ = ...`：每个 catch 必须有 ① 带模块前缀的日志、② 说明「为何忽略是安全的」的注释、③ 重新抛出之一。
- 接口只定义一次，别处 `import type`；barrel 文件只 re-export 不写业务逻辑。
- **作用域纪律**：只改任务要求的代码；顺手优化、顺手修 import、顺手现代化语法全部禁止——发现邻接问题先列出问用户，不顺手做。

## Gate 3 · VERIFY（验证）

五轴审查（每条都要证据）：

1. 正确性：实现满足需求分解中的每个维度；
2. 边界：空输入/超限/异常数据（见 `audit.md` 4.1）；
3. 错误处理：失败显式、可观测、不静默；
4. 集成：与相邻模块/外部系统的字段和调用一致；
5. 安全：无密钥泄漏、无注入、无越权。

跑测试 + 构建 + 相关校验脚本；修 bug 先写失败测试复现。

## Gate 4 · POLISH（打磨）

- 去 AI 味：命名自然、无空泛大词、无机械排比、注释解释「为什么」不解释「是什么」。
- 状态完整：加载/空/错误三态都有 UI；危险操作有确认。
- 可访问性与一致性：遵循项目已有风格；键盘/读屏可用（如适用）。
- 文档同步：README、CHANGELOG、活文档与本轮改动一致。

### 反 AI 审美清单（前端/视觉）

| AI 默认 | 为什么不行 | 正确做法 |
|---|---|---|
| 紫/靛渐变 | 模型默认调色板，千篇一律 | 用项目实际 design tokens |
| 到处 `rounded-2xl` | 毁掉圆角层级 | 跟随设计系统的圆角刻度 |
| 重阴影 `shadow-xl` | 视觉噪声 | 仅设计系统明确要求处 |
| 巨 padding `p-12` | 破坏层级、浪费空间 | 用一致间距刻度（4/8/12/16/24） |
| 通用 hero 段 | 模板感、与内容无关 | 内容驱动布局 |
| Lorem ipsum | 掩盖真实长度问题 | 用代表性真实数据 |
| 居中卡片网格 | 无信息层级 | 按重要性布局 |
| 装饰性 emoji | 生产环境不专业 | 用设计系统图标 |
| 任意像素值（13px/2.3rem） | 脱离刻度 | 保持在刻度上 |

### 四态 UI（数据组件必须）

`Loading → Empty → Error → Success` 四态显式处理：骨架屏 + aria-busy / 引导 CTA / 可重试 + 错误码 / 实际内容。禁止「加载白屏、出错崩溃、空数组什么都不画」。

### a11y 底线（WCAG 2.1 AA）

键盘可达（Tab 遍历、Enter/Space 触发）；纯图标按钮有 `aria-label`；表单有 label；颜色不是唯一信息载体；正文对比度 ≥4.5:1；焦点可见。

### 导入三段式

`[标准库]` 空行 `[第三方]` 空行 `[本项目/相对路径]`，段内字母序，禁止通配导入。

## 红名单（任一命中 = 停下）

- 单次提交 ≥100 净新增行；文件 >500 / 函数 >120 / 嵌套 ≥4；
- 变量名 `data/tmp/info/result`；空 catch / 裸 `unwrap()` / `as any`；
- 同一接口定义两处 + 用 adapter 桥接；
- 组件没有四态；UI 全是圆角/紫渐变/巨 padding；
- 没跑端到端就宣称「完成」；决策回复没有文件:行号锚点；
- 超出任务作用域（「顺手整理」）；TODO 没有 owner/issue。

## 最终验证清单（交付前最后一遍）

按 DECIDE → BUILD → VERIFY → POLISH 逐门自查：需求分解、证据锚点、撤回、now/later；切片提交 + 量化限制；五轴结论 + 端到端真实跑过；无 AI 味 + 四态 + a11y + 文档同步。任何一项未勾 = 未完成，回到对应门。

## 项目活文档约定（长项目）

长项目在项目根维护四份活文档，随改随更，不攒到结尾：

- `requirements.md`：范围与意图（living）；
- `plan.md`：当前实现计划（写新计划前把旧计划归档到 `design-archive/plan.<时间戳>.md`）；
- `implementation.md`：当前实现状态；
- `deployment.md`：部署记录。

## 提示与对话预算（AI 协作）

- 4S 法则：描述时给 Situation（现状）/ Spec（规格）/ Style（风格与版本）/ Scope（边界），一次给全，减少来回。
- 对话轮次预算：1–3 轮高预算（充分理解）、4–8 轮中、9–15 轮低；超过 15 轮上下文碎片化，重新开一轮而不是硬续。
- 迭代反馈每轮 ≤5 条，避免模型混淆；锁定版本时要求输出完整最终产物。

## 与审查流程的关系

- 四门是「写的时候」的关卡，`audit.md` 是「交付前」的自审；两者都要走，不互相替代。
